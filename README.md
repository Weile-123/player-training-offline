# 王牌训练师训练馆经营版

当前入口为经验成长与多球员训练馆经营版，基础体力为 20。手动只训练选中的一名球员，消耗其 1 点体力，冷却 1 秒；之后补招的新人首球也至少等待 1 秒。维持／成功／大成功概率为 30%／60%／10%，分别获得 8／12／20 XP；Lv.L 升一级需 `ceil(20+6L+0.15L²)` XP，每级沿用原算法尝试分配 10 点属性，最高 Lv.99。详细规则见 [游戏玩法设计方案](docs/游戏玩法设计方案.md)。

训练位数等于馆级，Lv.1 一位，Lv.8 八位；开局一人，新增空位由玩家免费招募。Lv.2 需累计 60 声望与两次有效推荐，同时免费解锁在线自动与30分钟离线训练，基础2秒／球；自动项目每级缩短0.2秒并使自动每球额外获得1XP，五级为1秒／球、每球额外5XP。离线课表五级依次扩到45／60／90／120／180分钟。各球员分别保存经验、体力、课程、合作、冷却和自动状态，自动中的同一球员暂停手动投篮。离线只训练开启自动的球员，沿用器材、课程和经验规则；超时只恢复体力。没有自动推荐或自动招募。

保留四种训练计划、十球课程、可选赞助合作、八级球馆、六类项目、运动饮料、背包、校友与双图鉴。器材库V3已全面重写为35件、14类，总标价306券；全馆共享，每类只启用一件。覆盖容量、恢复、课程、通用经验、自动经验、离线时长、品牌、合作与六维专项。每课基础返4体力，器材追加上限随馆级为1／1／2／2／2／3／3／3。推荐基础档位券仍为0–5；培养奖金取“Lv.10+首发3券、Lv.15+全明星7券、Lv.20+巨星12券、Lv.25+传奇18券”满足的最高累计档，加已完成合作与器材，总券最高33。六项目满级共504券，连同全部器材标价810券。

器材有空位且无同类时买入即生效；已有同类或位置满时先确认替换，旧件入仓。仓库可装回或按记录实付净价半价出售，售后图鉴保留。合作器材需实际启用完成两个完整10球课程，资格取得后换下仍保留；品牌声望按实际培养均值精确结算。离线器材延长15／30／60分钟，连同项目最多240分钟，每球经验与在线自动一致。旧档下架件全额退券、降价退差、涨价不追收、旧收藏留档；未领取旧离线按迁移前快照结算。完整清单见[新版器械表](docs/新版器械表.md)，结果见[重写与测试报告](docs/器材库重写与测试报告.md)。

35件名称和图片现已逐件复用原版成对资源，逻辑ID与原图ID分别记录。价格复核后仍全部保留，总标价306券；[后期赞助券方案](docs/器械价格复核与赞助券消耗方案.md)提出自愿36券精选招生，已做影子试验，尚未实装收费招募。

身价采用 `320×(L+1)³` 再乘器材百分比，不再逐球大成功复利。离线与旧档规则见 [离线训练实现与验收](docs/离线训练实现与验收.md)。本轮奖金与自动效率已落地，配对试算见 [培养收益与自动效率调整报告](docs/培养收益与自动效率调整报告.md)。原 [培养收益优化方案](docs/培养收益优化方案.md)保留提案与V4复审背景；旧价格数值见 [11月12日测试报告](docs/经验成长与多球员训练测试报告.md)。训练及推荐面板显示下一奖金的等级／模板差距、属性剩余价值与按当前配置估计的训练时间，预测不保证模板获得时间。

当前支持本地在线与离线训练，Timeflow服务端、双榜和其余四种消耗品未开放，生产上报仍需相应后端与验收。[11月12日全流程审查](docs/游戏全流程审查报告.md)保留为历史基线，不能将其中旧价格和离线未开放的结论套用于当前版本。

## 本地运行

```sh
npm ci
npm run dev
```

开发地址为 [127.0.0.1:5174](http://127.0.0.1:5174)。已有 `node_modules` 时可直接运行 `npm run dev`。运行 `npm run build` 后使用 `npm run preview` 查看生产构建，预览地址为 [127.0.0.1:4174](http://127.0.0.1:4174)。

常规回归使用 `npm test`，渲染回归使用 `npm exec -- vitest run --config vitest.renderer.config.ts`。当前器材试算使用 `node scripts/run-gym-equipment-balance-v3.mjs`，默认64种子；追加 `offline` 重跑离线饱和试验。从零经营使用 `node scripts/run-gym-equipment-v3-journey.mjs`，当前新库与旧库历史数据在 `docs/balance/experiments.json` 中区分。运行 `node scripts/export-gym-equipment.mjs` 可重新导出当前表与CSV。

## 项目配置

游戏使用本地美术和独立的 `gym-management-v1` 浏览器存档及备份，当前平衡标记为 `balanceVersion: 3`。已有档先校验旧 payload：缺失平衡版本或版本 1 的当级 XP 按旧、新需求比例映射，版本 2 不再缩放 XP；旧在训体力超出新容量则截断，校友历史体力保留。原等级、属性、球员、券、声望、项目、RNG、图鉴与校友保持，不追发升级或历史奖金。更早无 XP 的档补 0、无自动的档补关闭，旧冷却与合作迁入原球员，新增训练位保持空位。旧馆级与项目不回退，历史购买不追溯重算。原版合同存档继续保留在原键，平台技能以项目内 `hupu-ai-game-skills` 为准。

球员肖像与资料沿用已有虎扑适配与本地回退。新模板会从经营收藏恢复上报队列。正式模板上报使用 `VITE_GYM_API_BASE` 与 `VITE_GYM_ENV_ID`，需接入对应活动的统计后端。本地开发只记录收藏，部署时通过安全环境配置提供服务地址与活动环境。
