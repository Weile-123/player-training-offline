# 王牌训练师训练馆经营版

当前入口为经验成长与多球员训练馆经营版，基础体力为 20。手动只训练选中的一名球员，消耗其 1 点体力，冷却 1 秒；之后补招的新人首球也至少等待 1 秒。维持／成功／大成功概率为 30%／60%／10%，分别获得 8／12／20 XP；Lv.L 升一级需 `ceil(20+6L+0.15L²)` XP，每级沿用原算法尝试分配 10 点属性，最高 Lv.99。详细规则见 [游戏玩法设计方案](docs/游戏玩法设计方案.md)。

训练位数等于馆级，Lv.1 一位，Lv.8 八位；开局一人，新增空位由玩家免费招募。Lv.2 需累计 60 声望与两次有效推荐，免费解锁基础 2 秒／球的在线自动，项目每级缩短 0.2 秒，最高五级为 1 秒／球。各球员分别保存经验、体力、课程、合作、冷却和自动状态，自动中的同一球员暂停手动投篮。没有自动推荐或自动招募，关闭或离开游戏仅恢复体力，不追投漏过的自动球。

保留四种训练计划、十球课程、可选赞助合作、八级球馆、五类可购项目、94 件器材、运动饮料、背包、校友与双图鉴。每课基础返 4 体力，器材追加上限随馆级为 1／2／2／3／3／4／4／4。推荐基础档位券仍为 0–5；培养奖金取“Lv.10+首发 2 券、Lv.18+全明星 6 券、Lv.25+巨星 12 券”满足的最高累计档，再加已完成合作与器材，总券最高 27。项目逐级费用为 `ceil(基价×(9/5)^(级数−1))`，五个可购项目满级共 458 券。

身价采用 `320×(L+1)³` 再乘器材百分比，不再逐球大成功复利。本轮只调整现有曲线、课程与奖励／费用，离线投篮、Timeflow 平台接入与双排行榜继续延后。当前数值观察与验证范围见 [经验成长与多球员训练测试报告](docs/经验成长与多球员训练测试报告.md)。

当前是本地在线主要流程可玩的版本，整份设计尚未全部交付。离线投篮、双榜和其余四种消耗品未开放，生产上报仍需相应后端与验收。真实浏览器、从零合法回放和预置测试的范围，以及现存节奏和经济问题，见 [游戏全流程审查报告](docs/游戏全流程审查报告.md)。

## 本地运行

```sh
npm ci
npm run dev
```

开发地址为 [127.0.0.1:5174](http://127.0.0.1:5174)。已有 `node_modules` 时可直接运行 `npm run dev`。运行 `npm run build` 后使用 `npm run preview` 查看生产构建，预览地址为 [127.0.0.1:4174](http://127.0.0.1:4174)。

常规回归使用 `npm test`，渲染回归使用 `npm exec -- vitest run --config vitest.renderer.config.ts`。使用 `npm run simulate:gym` 重跑默认 100 种子的经验、器材和多人训练模拟；`npm run simulate:gym-economy` 回放从零经营。本报告的经营参数为 `GYM_ECONOMY_SEEDS=10`、`GYM_ECONOMY_SECONDS=3600`，输出更新至 `docs/balance`，方法与边界见测试报告。

## 项目配置

游戏使用本地美术和独立的 `gym-management-v1` 浏览器存档及备份，当前平衡标记为 `balanceVersion: 3`。已有档先校验旧 payload：缺失平衡版本或版本 1 的当级 XP 按旧、新需求比例映射，版本 2 不再缩放 XP；旧在训体力超出新容量则截断，校友历史体力保留。原等级、属性、球员、券、声望、项目、RNG、图鉴与校友保持，不追发升级或历史奖金。更早无 XP 的档补 0、无自动的档补关闭，旧冷却与合作迁入原球员，新增训练位保持空位。旧馆级与项目不回退，历史购买不追溯重算。原版合同存档继续保留在原键，平台技能以项目内 `hupu-ai-game-skills` 为准。

球员肖像与资料沿用已有虎扑适配与本地回退。新模板会从经营收藏恢复上报队列。正式模板上报使用 `VITE_GYM_API_BASE` 与 `VITE_GYM_ENV_ID`，需接入对应活动的统计后端。本地开发只记录收藏，部署时通过安全环境配置提供服务地址与活动环境。
