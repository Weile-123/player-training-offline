## 本轮发帖、广告与本地测试

使用 [openPostEditor](../hupu-skills/skills/colorbox-request-bbs-open-post-editor/SKILL.md) 和 [completeRewardVideo](../hupu-skills/skills/colorbox-vatask-complete-reward-video/SKILL.md)。SDK 使用本项目 Shaper 宿主注入的当前版本，移除原游戏固定旧版脚本回退；活动身份固定来自技能包，宿主应用不匹配时拒绝调用和发奖。发帖目标每次读取本项目 `bbsConfig.get()`；无有效标签时四个专区/话题字段全部省略，不导入旧游戏发帖目标。

- 有模板且未满级的球员显示“分享·等级+3”，每名球员仅一次；增加真实等级、属性与匹配结果，最高 99 级，不伪造训练次数或课程。
- 发帖先打开自定义编辑弹窗，再由玩家点击“发帖分享”唤起官方编辑器。仅 `code=200` 认定打开成功并领取奖励；不会自动发布帖子。取消、失败、超时、旧局或配置切换均不发奖。
- 体力为零时出现“体力回满”。全馆第一次通过分享领取，此后通过广告领取，次数随进度保存；自然恢复少量体力不影响已开始的回满流程。
- 每份合作左侧加入广告“一键完成”，仅 `code=200 && data.rewarded===true` 成功。完成合作后在推荐时结算，不直接发券，也不增加训练/课程或器材资格；更换合作需先确认旧进度清空。无模板 0 券、重复模板合计 1 券规则保留。
- “本地测试”仅 DEV 且精确 localhost/loopback 地址显示，包含跳过发帖、跳过广告。默认关闭，刷新恢复，不在生产环境生效。

界面与接口测试使用可控平台模拟，不曾实际发帖、观看广告或调用云服务。官方编辑器、广告任务额度及回调仍需在本项目虎扑活动页进行真机验收。

其他本轮调整：最后球员推荐后不再自动弹招募；达成升馆条件时自动展示升级页、关闭后红点保留；最高身价卡与离线头像使用对应级别完整包边，传奇动态；镁粉 2 券/后续 30 次大成功，团队补给 3 券。旧版已购买并启用的镁粉剩余次数不会丢失。

## 离线收益：已准备服务端适配，尚未启用平台结算

已阅读 [Shaper Timeflow 技能](../hupu-skills/skills/shaper-timeflow/SKILL.md)、工作区接入、认证、BFF 路由、协议与 SDK 使用说明。它不是 `ColorboxAI` 的前端离线收益函数，官方要求：

> 生产接入只有一条链路：Browser -> application BFF -> X-Shaper-Token public Timeflow endpoint

> 正式浏览器不得持有或计算 `SHAPER_TOKEN`/HMAC。

技能的“工作流 1”还要求先完成平台注册、定义提交、六组权威回放验证和激活；不能把本地结构检查或模拟返回描述成已接通平台。

现有项目是 Vite 前端，没有可复用的应用 BFF、服务端用户与球馆归属绑定、服务端球馆状态数据库或本项目 CloudBase 环境配置。提供的凭据文件包含 Shaper 授权字段，不能替代这些业务后端条件。`state.py current` 已运行，返回该应用交付状态尚未初始化；本轮没有初始化发布流程或注册、部署任何云资源。

本轮新增 [server/timeflow.mjs](../server/timeflow.mjs)：

- 从最新技能包的公开包入口加载 Timeflow SDK 0.0.1，身份读取本项目配置。
- 仅允许固定的结算、报告读取与 ACK 路径；凭据与签名只在服务端产生，不提供通用代理。
- 要求可信后端提供已验证的应用/环境/球馆绑定，以及原子落地 `applyOnce`，未提供即拒绝初始化。
- 完整报告必须先原子写入球馆进度与唯一结算号，再 ACK。ACK 中断后使用同一结算号续办，落地端返回 `replayed`，避免再次发奖。
- 空报告保留待处理状态；网络异常不自动重试；不由浏览器生成平台结算 `from/to`。

这是服务端协议适配层，**不是已部署的 BFF**。没有将其连入前端 store；当前离线投篮、经验、课程、模板变化仍由现有 `settleOfflineGym` 和本地事务统一结算，避免平台与本地重复发奖。当前球馆按体力恢复、逐球随机结果、课程和器材计算，不能用简单线性经验流替换而改变数值。

正式启用仍需完成以下工作：

1. 在本项目可信后端验证虎扑身份，持久保存应用/环境→工作区和用户→球馆的归属关系，执行动作授权与共享限流；前端自报 PUID、scope 或 workspace 均不作证明。
2. 将现有离线规则移到可信服务端，确定随机成长的权威规则与版本；保留等级 99、自动训练开关、球馆离线时长和课程规则。
3. 注册工作区与 scope，提交规则定义，取得平台 `1h / 1d / 30d / window / segment-equivalence / receipt-replay` 六组回放结果，通过后激活。
4. 数据库事务同时保存离线结果、报告和唯一结算号；在明确切换点停用该球馆的本地离线发奖路径。不能在平台请求失败后为同一区间再运行本地发奖作为兜底。
5. 通过 `ColorboxAI.cloud.request({auth:true, envId})` 连接本项目 BFF；完成登录、断网续办、多端、重复报告和 ACK 中断真机验证后再开启。

本地验证命令：`node node_modules/vitest/vitest.mjs run scripts/timeflow.test.ts`。21 项协议测试通过，覆盖签名/固定身份、禁止任意路径与区间、空报告、写入失败、ACK 失败重放和网络不重试。测试使用内存传输与模拟事务，没有进行真实平台调用；这不代表平台 validate 或真机验收已经通过。
