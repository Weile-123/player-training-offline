本地维护的渲染源码位于 vendor/preact，保留 MIT 许可证和 LOCAL-CHANGES.md。不是对压缩包替换字符串，也没有将域名拆分、编码或换成假域名。

- 内部用数字区分 HTML/SVG 上下文。
- HTML 元素直接用 createElement 创建。
- SVG 从 index.html 的固定 template 中克隆浏览器已解析的正确元素，保留真实 SVG 类型、属性、样式与事件。
- 不将用户名、网络响应或其他动态内容传给 HTML 解析器。
- 删除未使用的原始 HTML 注入功能，调用时明确报错。MathML 不受支持，新 SVG 标签须补充模板和测试。
- 游戏数值、存档格式、奖励规则及线上请求协议未修改。

## 提交审核说明

### 开发环境 Loading 后黑屏修复

发现 Vite 仅预打包 Zustand 时，将本地 Preact 源码一并嵌入 `node_modules/.vite/deps/zustand.js`，与页面直接使用的渲染器形成两份 hooks 实例。Loading 不读取 Zustand，进入首页才暴露冲突。已在 Vite 中排除 Zustand 和 zustand/vanilla 的依赖预打包，让它们与页面统一引用同一份源码。

用独立 Vite 开发服务器检查实际返回的模块：Zustand 现从 `/node_modules/zustand/esm/index.mjs` 加载，直接引用 `/vendor/preact/compat/src/index.js`，不再嵌入第二份渲染器。新增从 Loading 到真实动态导入首页、再打开图鉴的启动回归测试；新渲染专项现为 11 项，通过。已有浏览器如仍缓存旧模块，需要重启开发服务器并强制刷新；不需要清除游戏存档。

本版不再需要针对旧 React DOM 的三个压缩行申请豁免。旧 `React发布审核复核说明.md` 是历史分析，不是当前包的渲染实现说明。当前发布包中的 REVIEW-NOTES.md 使用本文件，REVIEW-EVIDENCE.json 绑定当前 JS 哈希及扫描结果。
